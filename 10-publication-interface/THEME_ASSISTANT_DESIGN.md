# 对话式选题助手设计 / Theme Assistant Design

本文定义法师与创作者的对话式选题助手。决策依据：`PRD_DRAFT.md` 的 D2（对话式）、D5（只做案例检索推荐）、D3（创作者登录）、D8（选题单网页查看+复制）、D11（AI 功能范围）。

## 1. 定位与边界

助手帮助法师/创作者从弘法意图出发，通过多轮对话找到资料库中**已发布**的案例。它是检索与解释的界面，不是内容生成器。

硬性边界：

```text
只做：澄清需求、检索案例、解释推荐理由、把选中的案例组成选题单
不做：生成或虚构案例内容、回答教理问题、评价案例真假、推荐库外材料
```

用户问教理问题时，用固定话术引导到已审核的导读文章或搜索页，不展开回答（D5）。

## 2. 对话状态机

```text
GREETING
  → SLOT_COLLECTION   （收集选题条件，AI 追问）
  → RETRIEVAL         （确定性检索，非 AI 生成）
  → RECOMMENDATION    （AI 从候选集选择并解释）
  → REFINEMENT        （用户反馈，调整条件后回到 RETRIEVAL）
  → SELECTION         （用户把案例加入选题篮）
  → BRIEF             （确定性模板组装选题单，非 AI 生成）
```

需要收集的条件（slot）与 PRD 的推荐输入字段一致：

| Slot | 必需 | 缺省处理 |
|---|---|---|
| `topic` 主题 | ✅ | 缺失时必须追问 |
| `audience` 受众 | 否 | 默认为"普通信众" |
| `duration` 时长/形式 | 否 | 不限制 |
| `preferred_case_period` 时代偏好 | 否 | 不限 |
| `preferred_source_type` 来源类型偏好 | 否 | 不限 |
| `case_tone` 语气偏好 | 否 | 不影响事实，只影响排序 |
| `avoid_types` 回避项 | 否 | 无 |

规则：

1. 一次只追问一个最关键的缺失 slot，不要连珠发问。
2. 澄清最多 3 轮；之后带缺省值继续，用户可随时补充或修改条件。
3. 用户在任意轮次可以直接给完整描述（"8 分钟视频，临终助念，现代案例，给家属看"），助手应一次填满多个 slot 并复述确认。

## 3. 每轮 AI 的职责拆分

对话不是"一个大模型随便聊"，而是按轮次拆成职责单一的子任务，每个子任务独立 prompt、独立校验：

| 子任务 | 输入 | 输出 | 职责边界 |
|---|---|---|---|
| `slot_extraction` | 用户最新消息 + 当前 slots | 更新后的 slot JSON | 只提取和合并条件，不聊天 |
| `clarification` | 当前 slots | 一句追问 | 只问一个最关键缺失项；无缺失时不触发 |
| `retrieval` | slots | 候选案例集 | **确定性代码执行**，不是 AI；全文+标签+语义混合检索 |
| `rank_and_explain` | slots + 候选集（仅公开字段） | 不超过 5 条推荐，每条含 `why_relevant`、`recommended_usage`、`risk_notes` | 只能从候选集中选；只写推荐理由，不复述案例内容 |
| `refine_intent` | 用户反馈 + 当前 slots | 更新后的 slots 或排序权重 | 把"太玄了""要现代的"翻译成条件调整 |
| `brief_assembly` | 选题篮中的案例 ID | 选题单 | **确定性模板组装**，不是 AI（见第 6 节） |

展示给用户的案例卡片内容（标题、摘要、出处、可信度、风险标签）**直接取自数据库已发布字段**，AI 不重写。AI 只生成"为什么适合你的选题"这段解释。

## 4. 防虚构机制（硬约束，由确定性校验器执行）

1. `rank_and_explain` 输出的每个 `case_id` 必须属于当前候选集；出现候选集外的 ID，整批推荐被校验器拒绝。
2. 推荐理由中的事实性陈述（人名、时间、地点、瑞相）必须能在该案例的已发布字段中找到；找不到则该条理由被拒绝。
3. 候选为空时，助手必须如实说明"当前库内没有足够合适的案例"，并建议放宽哪个条件；**禁止凑数**（与 PRD Success Criteria 一致）。
4. 校验连续 2 次失败时降级：直接展示候选列表（不带 AI 解释），并提示"智能推荐暂时不可用"。
5. 任何情况下 AI 输出不接触受限原文；候选集只包含已发布字段（与 G16 一致）。

## 5. 排序逻辑

基础分由确定性代码计算：

```text
score = semantic_relevance
      + tag_match
      + provenance_quality
      + narrative_clarity
      + video_fit
      - privacy_risk
      - copyright_risk
```

各因子定义见 `PRD_DRAFT.md` 的 Ranking Factors 表。`refine_intent` 可以调整权重或添加过滤条件；每次调整记入会话日志，保证推荐可复现。

## 6. 选题篮与选题单

- 选题篮保存在创作者登录账号下（D3），跨设备可用。
- 选题单由**模板组装**（D11）：从案例记录直接填充 PRD 的 Creator Brief 各节（主题、案例顺序、讲述点、出处、风险、教理边界、其他解读），不经 AI 生成，因此无需额外 AI 验收。
- 交付形式：网页查看 + 复制文本（D8）。不导出文件，不生成讲稿。

## 7. 界面布局

```text
┌──────────────────────┬───────────────────────────┐
│ 对话流                │ 推荐案例卡片（实时更新）    │
│ 用户：……              │ ┌───────────────────────┐ │
│ 助手：想确认一下，这   │ │ 标题 / 摘要            │ │
│ 期内容主要给谁看？     │ │ 出处 · 可信度 · 风险    │ │
│                      │ │ AI 推荐理由            │ │
│                      │ │ [加入选题篮] [查看详情] │ │
│                      │ └───────────────────────┘ │
│                      │ 选题篮（3）→ 生成选题单     │
└──────────────────────┴───────────────────────────┘
```

推荐卡片与对话流同屏，避免用户在长对话里翻找案例。

## 8. 会话日志与可复现

每轮记录：用户输入、slot 快照、检索条件、候选集哈希、AI 原始输出、校验结果。会话可完整回放；一次推荐的"当时为什么推荐这五条"必须能事后回答。日志不含受限原文。

## 9. 空态与失败

| 情况 | 行为 |
|---|---|
| 候选为 0 | 如实说明，并建议放宽的具体条件（如"要不要包含古代案例？"） |
| 校验失败 2 次 | 降级为无解释的候选列表 + 提示 |
| 用户问教理 | 固定话术引导到导读文章或搜索，不回答 |
| 用户要求讲稿 | 说明产品不提供讲稿生成（D8），引导使用选题单 |
| 检索服务故障 | 明确报错，不假装返回结果 |

## 10. 验收标准

- 固定评测集：至少 10 个预设选题 brief，每个标注预期应命中的案例；top-5 命中率达到预设阈值。
- 整个评测集中：库外 `case_id` 出现 0 次；无依据推荐理由 0 条；教理自由发挥 0 次；凑数推荐 0 次。
- 同一选题重复提问，推荐结果可复现（候选集相同则结果相同）。
- 每轮对话的 slot 状态、检索条件、候选集哈希可从日志完整还原。
