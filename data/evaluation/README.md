# 质量评测 / Evaluation

本目录存放 ROADMAP 2.3 第①步的固定评测资产：评分表、评测集、各版本基线报告。目的：让 `reader_generation` 与 `creator_analysis` 的 prompt 改版有可比的质量刻度（应对 KI-001、KI-002）。

## 文件

| 文件 | 内容 | 修改规则 |
|---|---|---|
| `quality_rubric_v1.md` | 两类产物的评分维度与 1–5 分锚点 | 用于基线后冻结；改动须存为 v2，旧报告不重打 |
| `eval_set_v1.json` | 10 个固定选题 brief（主题/受众/时长）+ 每个 brief 对应的案例与 v1 产物路径 | brief 只增不改；修正已有 brief 会使历史分数不可比，禁止 |
| `baseline_v1_report.md` | v1 基线评分（AI 评分，待负责人复核） | 已归档，不修改；复核修正记入新文件 |

## 评分人署名规则

1. 每份评分报告开头必须标明：**评分人（AI 写模型/工具名与日期；人工写姓名与日期）、评分表版本、评测集版本**。
2. AI 评分与人工评分**分开记录、互不覆盖**。人工复核 AI 基线时，不改动 AI 报告，另存 `baseline_v1_report.review-<评分人>-<日期>.md`，只写与 AI 评分不同的条目及理由。
3. 同一 artifact 版本若多人评分，各自独立成文；版本间对比以"同一评分人"的分数为准（避免评分者效应污染版本对比）。
4. 忠实度（A1）是硬门槛：任何评分人一旦触发，该产物读者侧记 0 并在报告中注明触发的引文证据。

## 新增案例如何补入评测集

1. 在 `eval_set_v1.json` 的 `briefs` 末尾追加新 brief：`brief_id` 顺延（B11、B12……），写明主题、受众、时长、所选 `case_id`、**选中依据**（为什么这个案例适合这个主题），以及产物路径。
2. brief 是"选题任务"不是"案例清单"：同一案例可被多个 brief 复用；一个案例没有合适 brief 时不必强行入选。
3. 若某讲法主题在现有案例中无匹配（如 v1 中的 B10 动物往生），照写 brief 并把 `case_id` 置 `null`、`status` 置 `corpus_gap`；该 brief 不计入均分，待语料补入匹配案例后改为 `scored` 并补评。
4. 新 brief 入选标准：主题须是法师开示中真实常见的主题（对应 2.3 第③步的教理主题库）；受众与时长须写成一次真实的开示/视频任务。

## v2（及以后版本）对比时怎么用

1. v2 prompt 产出后，对评测集中**全部 `scored` 状态 brief 对应的案例**跑 v2，产物存于各自 Run 目录，不要在评测集 JSON 里改 v1 路径——v2 产物路径记入 v2 评分报告。
2. 用**同一版评分表**（quality_rubric_v1）逐项打分，报告命名 `baseline_v2_report.md`（或 `comparison_v1_v2_report.md`），标注评分人。
3. 对比口径：逐维度对比均分 + 逐 brief 对比；ROADMAP 2.3 的验收线是"v2 评审分显著高于 v1 基线，且事实/版权硬指标不下降"——即忠实度（A1）不得出现 0，误读风险（B4）均分不得下降。
4. 若 v2 时代评测集已扩充（新增 brief），对比报告须分两栏：v1 已有 brief 的同集对比（主结论）+ 新增 brief 的 v2 单列分（参考）。
